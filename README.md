# يا ساتر! جتنا عزيمة — نسخة GitHub Pages الجماعية (حتى 10)

## طريقة التركيب (مرة واحدة)

1. افتحي https://console.firebase.google.com وأنشئي مشروعًا جديدًا بخطة **Spark** المجانية.
2. من Project settings > Your apps أضيفي تطبيق **Web (</>)** وانسخي firebaseConfig.
3. من Build > Realtime Database أنشئي قاعدة بيانات (احفظي عنوان **databaseURL** الحقيقي؛ يختلف حسب المنطقة). لا تختاري قواعد Test mode المفتوحة للجميع. في تبويب **Rules** الصقي **محتوى** ملف `firebase-rules.json` واضغطي Publish.
4. من Build > Authentication > Sign-in method فعّلي **Anonymous** ثم Save؛ ما يحتاج المشاركون يسجلون حسابات.
5. من Project settings في Firebase ضعي قيم بيانات تطبيق الويب في `firebase-config.js`. أبقي علامات التنصيص والفواصل كما هي. يجب أن يحتوي `databaseURL` على الرابط الحقيقي لقاعدة بياناتك.
6. على GitHub أنشئي مستودعًا عامًا وارفعـي **كل الملفات الموجودة في هذا المجلد إلى جذر المستودع**. افتحي Settings > Pages > Build and deployment > Deploy from a branch > main / (root) > Save.
7. رابط اللعب: `https://USERNAME.github.io/REPOSITORY/` (تستبدل القيم بأسماء الحساب والمستودع). لعبة الجهاز الواحد في `https://USERNAME.github.io/REPOSITORY/solo.html`.
8. إذا ظهر الخطأ `auth/unauthorized-domain`، افتحي Firebase Authentication > Settings > Authorized domains وأضيفي `USERNAME.github.io` (اسم المضيف دون https أو المسار).

## تجربة اللعب

- المضيفة تدخل اسمها وتضغط إنشاء غرفة، يظهر رمز من 6 خانات.
- كل واحدة تفتح رابط الدعوة، تكتب اسمها وتنضم. الحد 2–10 لاعبين.
- المضيفة تبدأ العزيمة، والجميع يصوّت من جهازه. تحديثات Firebase تظهر مباشرة.
- بعد 8 مواقف مرتبطة و3 تحديات، تظهر النتيجة والترتيب. صاحبة الغرفة تقدر تبدأ جولة ثانية.

## الملفات

- `index.html` صفحة اللعب الجماعي الأساسية.
- `online.js` منطق الربط والغرف والتصويت بدون Node.js.
- `game_data.js` المواقف والتحديات.
- `firebase-config.js` إعدادات مشروع Firebase (يجب تعديلها قبل اللعب الجماعي).
- `firebase-rules.json` قواعد الحماية (تلصق داخل Firebase Console ولا يكفي رفعها إلى GitHub).
- `solo.html` اللعب على جوال واحد بدون Firebase.
- `.nojekyll` لضمان نشر ملفات الموقع كما هي.

## تنبيهات

- **GitHub Pages ليس خادم غرف**: يستضيف الواجهة فقط. Firebase هو الذي يزامن بيانات الجلسات.
- الإعدادات العلنية (apiKey وغيرها من إعدادات تطبيق الويب) ليست مفتاح خادم سريًا؛ **لا ترفعي Private Keys أو Service Account JSON أو رموز وصول**.
- هذه نسخة تجريبية عائلية؛ يُراجع عدد المشاركين في واجهة اللعبة لكن لا يوجد حد صارم مفروض داخل قواعد قاعدة البيانات عند طلبات الانضمام المتزامنة جدًا. رموز الغرف ليست بديلًا عن نظام عضويات قوي، وكل شخص يعرف الرمز وله دخول مجهول يمكنه قراءة بيانات الغرفة. لا تستخدميها لمعلومات شخصية أو حساسة.
- لا تدخلي بيانات بطاقات أو صور خاصة في اللعبة؛ تحفظ القاعدة الأسماء ونتائج الجلسات، ولا تنظف الغرف القديمة تلقائيًا.
- تبقى المضيفة في الصفحة للتحكم بمراحل اللعب، وقد يتعذر استعادة دورها إن مسحت بيانات متصفحها.
- **لم يتوفر في هذه البيئة مشروع Firebase فعلي**، لذا تم اختبار بنية الملفات وصحة JavaScript محليًا، ولم يُختبر الانضمام المباشر عبر Firebase حساب حقيقي بعد.

## خطوة الربط المختصرة (بعد تفعيل GitHub Pages وإنشاء Firebase)

1. في Firebase: إعدادات المشروع ⚙ > General > Your apps > Web. أضيفي تطبيق ويب إن لم يكن موجودًا، ثم اختاري Config وانسخي قيم `firebaseConfig`.
2. في GitHub: افتحي الملف `firebase-config.js` وعدّلي القيم مع الاحتفاظ بكلمة `export` في بدايته. تأكدي من حقل `databaseURL` المطابق لعنوان قاعدة Realtime Database الفعلي، واحفظي التعديل عبر Commit changes.
3. في Firebase: Build > Realtime Database > Rules؛ امسحي النص القديم والصقي محتوى الملف `firebase-rules.json` من **هذه النسخة المصحّحة** ثم Publish. يجب لصق المحتوى وليس رفع ملف JSON إلى GitHub فقط.
4. اختبري الرابط من جوالين؛ الأول ينشئ غرفة والثاني ينضم باستخدام الرمز. لو ظهرت رسالة Authentication تأكدي من Build > Authentication > Sign-in method > Anonymous = Enabled.

ملاحظة الإصلاح: جرى إزالة استدعاء `childrenCount()` غير المتاح في لغة Firebase Realtime Database Rules؛ لذلك تحقق حد 10 لاعبين في واجهة التطبيق وليس قيدًا صارمًا على قاعدة البيانات.
